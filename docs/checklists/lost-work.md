# Lost-work fixes from upstream (Fix AI stage 2b)

`docs/design/upstream-sync.md` › Ported from upstream. Each row is a bug that lost or corrupted a person's work, and the file in the damaged shape it must still open.

| Check | How | Covered by |
|---|---|---|
| Page ruler guides survive save and reopen | Add ruler guides to a page and a frame, save, close, reopen: the guides are there; add another, save and reopen again: the file opens with all of them | `crates/format/src/page_guides_tests.rs` › `page_guides_survive_save_and_reopen_twice`; `crates/doc/src/guides_tests.rs` |
| A file saved with the page's guides twice opens | Open a file whose page has the `guides` key twice (saved by an earlier build after a reopen): it opens with both lists, the file's bytes are unchanged, and its next save opens | `page_guides_tests.rs` › `a_file_saved_with_the_page_guides_key_twice_opens_with_its_guides_and_saves_a_valid_file`; `guides_tests.rs` › `a_page_written_with_the_key_twice_opens_with_both_lists` |
| A NaN or infinity never makes a file that won't open | Save a document holding a NaN or infinite number (only reachable through a bug or a hostile plugin): it reopens with 0 there | `crates/format/src/null_numbers_tests.rs` › `a_document_holding_nan_and_infinity_saves_a_file_that_reopens` |
| A file saved with `null` numbers opens | Open a file an earlier build saved with `null` for a number: it opens, a toast says how many numbers were reset (English and Spanish), the file's bytes are unchanged, its next save is valid; File ▸ Import of it works too | `null_numbers_tests.rs` › `a_file_with_nulls_where_numbers_belong_opens_with_their_defaults_and_one_warning`; `crates/engine/src/non_finite_tests.rs` › `a_file_saved_with_null_numbers_opens_and_imports_with_a_note_and_stays_as_it_was`; `crates/ui-egui/src/lost_work_ui_tests.rs` › `null_numbers_and_numbers_that_arent_finite_are_explained_in_english_and_spanish`; `crates/mcp/tests/non_finite.rs` |
| Numbers that aren't finite are refused at the source | Set a text's line height to `NaN%` or letter spacing to `inf%` (Design panel, MCP `set_properties`): refused with a reason, nothing changes | `non_finite_tests.rs` › `a_line_height_or_letter_spacing_that_isnt_finite_is_refused`; `crates/mcp/tests/non_finite.rs` › `set_properties_refuses_a_line_height_or_letter_spacing_that_isnt_finite` |
| Imports never bring in a number that isn't finite | Import a file whose layers would get NaN or infinity: they come in at their defaults, with a note in the import report | `non_finite_tests.rs` › `an_import_with_numbers_that_arent_finite_comes_in_with_them_reset` |
| A crash during a version preview brings back your work | Edit a file, show an earlier version from Version history, quit the app by force, start it again: the recovered file is your working document, not the version; leaving a preview and restoring a version work as before | `apps/figcraft/src/recovery_tests.rs` › `a_crash_during_a_version_preview_recovers_the_working_document` |
| A save never drops images that weren't loaded | Open a file whose images together pass what Scrim reads from one file (4 GiB or 20,000 images; tests use a smaller budget): it opens without the ones past it and says they stay in the file. Edit, Save, and Save as a copy: a toast says every image was kept (English and Spanish), and each saved file holds all of them. With the original file moved away, a save is refused and writes nothing | `crates/engine/src/images_left_in_file_tests.rs`; `crates/format/src/image_budget_tests.rs`; `crates/ui-egui/src/lost_work_ui_tests.rs` › `a_save_that_kept_images_left_in_the_file_says_so_in_english_and_spanish` |
