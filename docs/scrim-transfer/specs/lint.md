# Spec: the design lint (`lint_design`, `ignore_lint`, `set_lint_profile`)

Scrim's deterministic design linter, written so it can be re-implemented without reading Scrim's TypeScript.

- **This file:** the model, the run order, profiles and ignores, the three MCP tools with their exact input and output, the shared helper functions (colour maths, parsing), the case-file schema, the known quirks, and the licence duties.
- **`lint-rules.md`:** every rule, one section each: what it checks, thresholds, the finding's `detail` template, its message verbatim, and its profile behaviour.
- **Cases:** `../cases/lint.json`, 88 cases generated by running Scrim's real tools (see §9).

Scrim sources this was read from (for archaeology only): `packages/engine/src/design/{lint,rendered,motionRules,overlap,sizeDuplicated,shorthandConflict,profiles,catalog,color,decls}.ts`, `packages/core/src/{lintConfig,shorthandForm,sizeHome,shorthands,motionShorthands}.ts`, `packages/engine/src/layout/clip.ts`, `packages/mcp/src/{designTools,lintTools}.ts`, `packages/engine/design-rules/`.

## 1. What the lint is

- A pure function of the document (plus, optionally, measured rects) that returns **findings**. It never writes.
- Rules come from two sources:
  - **Impeccable** (github.com/pbakaus/impeccable, v2.3.2, commit `1863a44b23bf`, Apache-2.0): a 41-rule catalog. Scrim ports **30** of them. The other **11 are registered but never reported** (§2).
  - **Scrim-native:** 4 rules (`root-overlap`, `text-occluded`, `size-duplicated`, `style-shorthand-conflict`).
- So **45 rule ids are known** (accepted by `ignore_lint`), and **34 can be reported**.
- Each rule has a **category**: `slop` (a tell of generated UI) or `quality` (a defect). There is no severity in the output. Six catalog entries carry `severity: "advisory"` upstream; Scrim ignores the field. What decides whether a finding counts is its **mode** under the artboard's profile (§4).
- Each rule has a **domain**, one of 7: `Color & Contrast`, `Copy`, `Imagery`, `Layout & Space`, `Motion`, `Typography`, `Visual Details`. It is the catalog's `skillSection`, or, for the 7 catalog rules with none, a fixed fallback (listed per rule in `lint-rules.md`).
- **Model-only vs rendered.**
  - 27 rules read only the document (declarations and text).
  - 7 need **measured rects**: `text-overflow`, `line-length`, `body-text-viewport-edge`, `clipped-overflow-container`, `hero-eyebrow-chip`, `text-occluded` and `root-overlap`.
  - Rects are canvas-space border boxes `{x, y, width, height}` that the studio measured in the browser. They are ephemeral editor state, never document data. A node without a rect is **skipped, never guessed**.
  - In the Rust fork the layout engine supplies them. Rule semantics stay the same.

## 3. Document data: `ScrimDoc.lint`

```ts
lint?: {                                   // optional; absent ≡ { profiles: {}, ignores: [] }
  profiles: Record<RootId, 'ui' | 'expressive'>;   // absent entry ≡ 'ui'
  ignores: Array<{ ruleId: string; nodeId?: NodeId; reason: string }>;  // ordered list
}
```

- It lives in the document, not in editor preferences, because it is design intent that a later session (human or agent) needs. It is persisted, undoable and never exported.
- **Validation** (refused on load / by the validator, code `bad_lint_config`):
  - `lint must be { profiles: {}, ignores: [] }` when either part is missing or of the wrong type;
  - `unknown lint profile <p> for <rootId>`;
  - `lint ignore needs a rule id and a non-empty reason: <JSON of the entry>`.
  - Entries naming deleted nodes are **allowed and kept** (undoing the delete revives them).
- **The one write operation, `set_lint`** (one undo step):
  - **Input:** `{ profiles?: Record<RootId, Profile | null>, ignores?: Array<{ ruleId, nodeId?, reason: string | null, index? }> }`.
  - **Profiles:** LWW per root. `null` deletes the entry.
  - **Ignores:** keyed by `(ruleId, nodeId ?? null)`.
    - A string `reason` re-reasons an existing entry **in place**, or appends a new one (at `index` when given, clamped).
    - `null` removes the entry. Removing an absent entry is a no-op.
  - **Inverse:** the exact inverse, carrying the removed entry's index so undo restores the order.
  - **Normalisation:** when both parts end up empty, `doc.lint` is deleted (absent, not empty).
  - **Refusals, verbatim:**
    - `unknown lint profile for <rootId>: <p> (expected ui | expressive)`;
    - `a lint ignore needs a rule id` (empty or whitespace `ruleId`);
    - `ignoring <ruleId> needs a non-empty reason` (non-null reason that is blank after trim).

## 4. Profiles and classification

Profiles are per root artboard.

| Profile | Summary (verbatim) | Rule changes |
|---|---|---|
| `ui` | `product UI and landing pages — every rule counts (the default)` | none |
| `expressive` | `posters, covers, editorial display type — relaxes rules aimed at UI type scales; contrast still counts` | `oversized-h1` **off**, `side-tab` **off**, `clipped-overflow-container` **off**, `text-occluded` **info** |

- **`ALWAYS_INFO`** = `size-duplicated`, `style-shorthand-conflict`: informational in every profile.
- **`NEVER_RELAXED`** = `low-contrast`, `gray-on-color`, `tiny-text`, `root-overlap`: always active (a Scrim test forbids any profile from listing them).

**Classification**, for each finding in run order:
1. **Profile:** the override when given, else `doc.lint.profiles[finding.rootId] ?? 'ui'`. Record `profiles[finding.rootId] = profile`.
2. **Ignores:** if an ignore matches (§5), the finding goes to **ignored** (with the matching ignore) and the next steps are skipped. Ignores win over everything, including `ALWAYS_INFO`.
3. **Mode:**
   - `ALWAYS_INFO` rule → `info`;
   - `NEVER_RELAXED` rule → `active`;
   - otherwise the profile's mode for the rule (`off`, `info`), or `active` when the profile does not list it.
4. **Bucket:** `off` → **relaxed**; `info` → **informational**; `active` → **active**.

Only active findings are counted. Each bucket keeps run order.

**The profile string agents see.** The tool descriptions embed `describeLintProfiles()`, verbatim:

```
'ui' = product UI and landing pages — every rule counts (the default); 'expressive' = posters, covers, editorial display type — relaxes rules aimed at UI type scales; contrast still counts (oversized-h1 relaxed, side-tab relaxed, clipped-overflow-container relaxed, text-occluded informational)
```

## 5. How an ignore matches a finding

The **first** ignore in list order matches when it has the same `ruleId` and one of these holds:
- it has no `nodeId` (document-wide);
- `ignore.nodeId` is the finding's node or one of its ancestors (walk `parentId` up from `finding.nodeId`);
- `ignore.nodeId` is in `finding.relatedNodeIds`. For example, ignoring `root-overlap` on either root of the pair covers the pair (case `ignore_lint/related-node`).

## 6. The MCP tools

All three answer with one text content block holding pretty-printed JSON (2-space indent), or an error (`isError: true`) whose text is the message alone.

### 6.1 `lint_design`

**Input:**
- `id?: string`: lint that node's subtree; omit for the whole document.
- `profile?: 'ui' | 'expressive'`: override every artboard's stored profile for this run. It writes nothing.

**Run** (both forms take the measured rects the server holds, possibly none):
- **With `id`:** `lintNode(doc, id, rects)`.
- **Without:** `lintDocument`. That is `lintNode` for each root in `rootIds` order, concatenated, then the `root-overlap` pairs appended (§7.4). Only a whole-document run ever reports `root-overlap` (case `root-overlap/subtree-run`).

**Error:** `node not found: <id>`.

**Output:**

```jsonc
{
  "target": "<id>" | "(document)",
  "profile": "<override>" | "<stored profile of the target's artboard, default ui>" /* id given */ | "per-artboard" /* no id, no override */,
  "profileSource": "override" | "document",
  "profiles": { "<rootId>": "ui" | "expressive" },   // ONLY roots that produced ≥ 1 finding (any bucket), first-seen order
  "violationCount": <active.length>,
  "byCategory": { "slop"?: n, "quality"?: n },       // active only, keys in first-seen order
  "byDomain": { "<domain>"?: n },                    // active only, keys in first-seen order
  "violations": [DesignViolation…],                   // active
  "informational": [DesignViolation…],
  "relaxedByProfile": [{ "ruleId", "nodeId", "nodeName", "rootId" }],
  "ignored": [{ "ruleId", "nodeId", "nodeName", "reason", "ignoreNodeId": "<id>" | null }]
}
```

`DesignViolation` (key order is not significant):

| Field | Meaning |
|---|---|
| `ruleId` | the rule id |
| `category` | `slop` / `quality` (from the registry) |
| `domain` | the reporting domain (§1) |
| `name` | the rule's name, verbatim (`lint-rules.md`) |
| `message` | the rule's description, verbatim (`lint-rules.md`) |
| `detail?` | evidence from this document; template per rule. Absent for rules without one |
| `nodeId`, `nodeName` | the flagged node and its `name` |
| `rootId` | the **top-level artboard** above the lint target, even when the target is a nested node. For `root-overlap`, the earlier root itself |
| `relatedNodeIds?` | other nodes the finding names. Present only when non-empty. Selecting the finding in the editor selects these too |

**Description, verbatim** (`<P>` = the profile string of §4):

```
Run the deterministic design-rule linter (vendored Impeccable anti-patterns) over a node subtree (pass id) or the whole document. Returns violations with node ids, the rule, its design domain, and why it is a problem. A whole-document run also flags root artboards whose measured rects overlap (root-overlap). Each artboard is judged under its lint profile, stored in the document (<P>); pass profile to judge everything in scope under one profile instead. The result names the profile used, lists informational findings and reasoned ignores separately, and counts only active violations. Run it on what you built before reporting done.
```

The `profile` parameter's description: `override every artboard's stored profile for this run`.

### 6.2 `set_lint_profile`

**Input:**
- `ids: string[]` (1–500): root artboard ids. Duplicates are collapsed, first-occurrence order kept.
- `profile: 'ui' | 'expressive'`.

**Behaviour:**
- For each unique id, in order:
  - `node not found: <id>` when the node is missing;
  - `lint profiles apply to root artboards; <id> is inside <parentId>` when it is not a root.
- The first failure aborts with nothing written.
- Roots whose stored profile already equals `profile` are skipped. `ui` is written as `null` (stored as absent).
- If anything changed, the tool applies **one** `set_lint` patch.

**Output:** `{ "roots": [{ "id", "name", "profile", "active", "relaxed", "ignored" }] }`, one entry per unique id. The counts come from `lintNode(doc, rootId)` classified under the stored profile **without measured rects**. That is a quirk: they can differ from `lint_design`'s (case `set_lint_profile/flow`). Informational findings are not counted.

**Description, verbatim:**

```
Set the lint profile of one or more root artboards, stored in the document (undoable, persisted, seen by every later session). Profiles: <P>. Use 'expressive' when the artboard is a deliberate display piece; 'ui' restores the default. Returns each root's profile and its finding counts.
```

### 6.3 `ignore_lint`

**Input:**
- `ruleId: string` (min length 1);
- `nodeId?: string`;
- `reason?: string`;
- `remove?: boolean`.

**Checks, in this order:**
1. **Unknown rule:** `unknown lint rule: <ruleId>. Known rules: <the 45 ids of §2 joined with ", ">`. Unported ids are accepted.
2. **Unknown node:** `node not found: <nodeId>`.
3. **Missing reason:** unless `remove === true`, the reason trimmed must be non-empty, else `ignore_lint needs a non-empty reason saying why <ruleId> is deliberate here`.

**Then:** the tool applies one `set_lint` patch: `{ ruleId, nodeId?, reason: remove ? null : trimmedReason }`.
- A blank `reason` that passes the checks is impossible, and a `PatchError` comes back as the error text.
- Re-ignoring an existing `(ruleId, nodeId)` replaces its reason in place.
- `remove` of an absent ignore succeeds as a no-op.
- The tool does **not** refuse contrast ignores, although its description says never to use them (case `ignore_lint/flow`).

**Output:** `{ "ignores": doc.lint?.ignores ?? [] }`, the full list after the write.

**Description, verbatim:**

```
Record a reasoned exception to one lint rule in the document (undoable, persisted, shown in the editor's Ignored group with its reason). With nodeId it covers findings on that node or inside it (pass an artboard root to cover the artboard); without, the whole document. reason is required and must say why the finding is deliberate. remove: true deletes the ignore instead. Prefer set_lint_profile for a whole expressive artboard; never ignore a real contrast failure.
```

### 6.4 The hint on every write tool

Every content-writing tool's description, and the server instructions, end with this text (it travels in descriptions because a new session has no memory of the rules):

```
 Before reporting the work done, run lint_design on what you built (id = its artboard root) and fix what it flags. When you make an artboard deliberately expressive (a poster, cover or editorial display type), call set_lint_profile with profile 'expressive' for it so lint judges it as such — <P>. Use ignore_lint only for one deliberate finding, with a specific reason; never to silence contrast.
```

## 7. The run (`lintNode(doc, targetId, rects?)`)

### 7.1 Scope

- **Subtree:** the target and its descendants in **pre-order** (a node, then its children in `childIds` order, depth-first).
- **`artboard`:** the top-level ancestor of the target (the target itself when it is a root). Every finding's `rootId` is this.

### 7.2 Order of findings

The order is part of the contract. The cases compare arrays in order.

1. **Per node, in pre-order.** For each node, in this order:
   1. `size-duplicated`, `style-shorthand-conflict`;
   2. `bounce-easing`, `layout-transition`, `image-hover-transform`;
   3. `overused-font`, `gradient-text`, `repeating-stripes-gradient`, then `side-tab` **or** `border-accent-on-rounded` (at most one), `gpt-thin-border-wide-shadow`, `cramped-padding`;
   4. text nodes only: `tiny-text`, `oversized-h1`, `extreme-negative-tracking`, `wide-tracking`, `all-caps-body`, `justified-text`, `gray-on-color` **or** `low-contrast` (at most one), `marketing-buzzword`.
2. **Rendered checks, only when a rect map is supplied** (it may be empty). Per node in pre-order:
   1. `text-overflow`, `clipped-overflow-container`;
   2. text nodes only: `line-length`, `body-text-viewport-edge`, `hero-eyebrow-chip`, `text-occluded`.
3. **Aggregates over the subtree:**
   1. `single-font`, `flat-type-hierarchy`, `monotonous-spacing` (attributed to the **target**);
   2. `nested-cards` (per inner card, pre-order);
   3. `em-dash-overuse`, `numbered-section-markers` (attributed to the target).
4. **Document runs only:** `root-overlap` pairs (§7.4), after every root's findings.

### 7.3 "Effective declarations"

Every rule reads a node's **effective declarations** `D`: the `layout` map, then the `style` map on top. A key set in both takes style's value. Keys whose value is `undefined` are skipped. Exceptions to this are noted per rule:
- the contrast background walk reads `style` only;
- the motion rules also read `states` and `media` maps;
- `size-duplicated` and `style-shorthand-conflict` look at both maps separately.

A value is a string or a number (`CssValue`).

### 7.4 `root-overlap` (document-level)

- **Candidates:** roots in `rootIds` order that have a rect.
- **Pairs:** every pair `(i < j)` whose rects intersect strictly: `a.x < b.x+b.w && a.x+a.w > b.x && a.y < b.y+b.h && a.y+a.h > b.y`. Touching edges do not count.
- **Attribution:** one finding per pair, attributed to the earlier root: `nodeId = rootId = a`, `relatedNodeIds = [b]`.
- **Detail:** `overlaps "<b.name>" by <W>×<H>`, where `W = round(min(right) − max(left))`, `H = round(min(bottom) − max(top))` (U+00D7 ×).
- **When it runs:** only when rects are supplied and the rule is not filtered out.

## 8. Shared helpers (the exact definitions rules cite)

**`px(v)`** (lint):
- a number → itself;
- a string matching `^(-?[\d.]+)px$` (after trim) → parseFloat of the number;
- a string matching `^-?[\d.]+$` → parseFloat;
- anything else (`%`, `em`, `rem`, multi-value, `var()`) → `null`.

**Other parsing helpers:**
- `lower(v)` = `String(v).toLowerCase()`, or `''` when undefined.
- `primaryFont(f)` = the text before the first `,`, trimmed, with one leading and one trailing `'`/`"` removed, lower-cased; `null` if empty.
- **`trackingEm(D)`** (`letterSpacing` as a fraction of the font size):
  - a string ending in `em` → parseFloat;
  - else `px(letterSpacing) / px(fontSize)` when both are known and the size is non-zero;
  - else `null`.
- **`isText(n)`** = `type === 'text'` and `text` is a non-empty string.

**Inherited values** (rendered rules only):
- `inherited(n, key)`: the node's own effective value, else the nearest ancestor's.
- **`fontSizePx(n)`:** the inherited `fontSize`;
  - a px value via `px` → that;
  - `^([\d.]+)r?em$` → that × 16;
  - otherwise **16**.
- **`lineHeightPx(n)`:** the inherited `lineHeight`;
  - a number `< 5` → × font size; any other number → that many px;
  - a string ending `px` → that; `%` → /100 × font size; `em` → × font size; a bare number string → × font size;
  - otherwise `1.2 ×` font size.

**Colour parsing, `parseColor(s)`** (vendored from Impeccable, extended with hex). Lower-case and trim first, then:
- empty or `transparent` → `null`;
- the names `white black red green blue gray grey` map to `#ffffff #000000 #ff0000 #008000 #0000ff #808080 #808080`;
- `#rgb` and `#rrggbb` → alpha 1. **Other hex lengths → `null`.**
- otherwise the first match of `rgba?\((\d+),\s*(\d+),\s*(\d+)(?:,\s*([\d.]+))?\)`, **unanchored**: integer channels and comma syntax only, alpha default 1;
- else `null`.

**Colour classification:**
- **`isNeutralColor(s)`:**
  - `undefined`, empty or `transparent` → true;
  - unparseable → **false** (errs toward detecting);
  - else `max(r,g,b) − min(r,g,b) < 30`.
- **`hasChroma(s)`:** parseable and spread `≥ 30`.
- **`isGrayColor(s)`** (a Scrim change): parseable, neutral, and relative luminance in `[0.03, 0.70]` (≈ `#323232`…`#dadada`). Near-black and near-white are not "gray".

**Contrast maths:**
- **`relativeLuminance`:** each channel `c/255`, then `c ≤ 0.03928 ? c/12.92 : ((c+0.055)/1.055)^2.4`. L = `0.2126 R + 0.7152 G + 0.0722 B`.
- **`contrastRatio(a, b)`** = `(max(La,Lb) + 0.05) / (min(La,Lb) + 0.05)`. Alpha is ignored.

**Number formatting** (it matters for `detail` strings):
- `round` is JavaScript `Math.round`: half toward +∞.
- `toFixed(n)` is JavaScript's: the decimal nearest the exact binary value, **ties away from zero**. For example `(-0.0625).toFixed(3)` = `-0.063` (case `extreme-negative-tracking/positive`). Rust's `{:.3}` may differ on ties; emulate JS.
- Lengths and slices of `text` are in **UTF-16 code units**.

Generated by `/private/tmp/…/scratchpad/transfer/lint-analyze/cases-lint.mjs`, kept outside the repo. It runs Scrim's built packages through the real MCP server in-process (the `scrim` CLI's path) at Scrim commit `f2b1bdb`.

```jsonc
      "tool": "lint_design" | "ignore_lint" | "set_lint_profile",
      "args": { … },
      "expect": { "isError": false, "result": { …the tool's JSON… } }   // or isError true, result = the message string
    }],
    "docAfter": null | { "lint": … }      // the document's lint config after the steps, when they changed it
  }]

```

**How to use a case:**
- Load `doc`.
- If `rects` is non-null, give the lint exactly that rect map. A node absent from it has no rect.
- Run the steps in order. Compare each result for deep equality: arrays in order, object keys in any order.
- When `rects` is `null`, the server held no measurements. `lint_design` still passes an empty map, so the rendered rules run and find nothing.
- **Rendered cases** (`needsRects: true`) put hand-chosen rects where Scrim would use the browser's measured layout. A Rust port should feed the same rects through whatever seam replaces measurement, not its own layout. Its layout engine should produce equivalent rects for these documents, but the cases do not depend on that.

## 10. Quirks and underspecified points (as shipped; port them or decide)

1. **Own values only:**
   - Contrast, `tiny-text`, `oversized-h1`, the tracking rules and `all-caps-body` read the node's **own** `color`, `fontSize`, `letterSpacing` and `textTransform`, never inherited ones. A text with no own colour is never contrast-checked (case `low-contrast/negative`, node `c`).
   - em, rem and % sizes are never judged by the model rules.
2. **Background walk:** `resolveBackground` reads `style.background ?? style.backgroundColor` only, never layout. It skips values `parseColor` cannot read (gradients, images, `transparent`, 4/8-digit hex) and walks up.
3. **Border sides:** the side and border parser splits on whitespace, so `rgb(220, 38, 38)` becomes `rgb(220,`. The detail reads `3px rgb(220,` (case `border-accent-on-rounded/positive`). The side test never reads `borderWidth` / `borderColor` (case `side-tab/quirk-borderWidth-group-ignored`).
4. **Shadow blur:** `gpt-thin-border-wide-shadow` takes the blur as the third `px`-suffixed number, so `0 8px 32px …` reads blur 0 (case `…/quirk-unitless-zero`).
5. **`text-overflow`:** fires for any node type, not only text. It measures against the parent's border box, and horizontally only.
6. **`set_lint_profile` counts:** computed without rects, so they omit every rendered rule.
7. **`profiles` in `lint_design`:** lists only roots with at least one finding.
8. **Contrast ignores:** `ignore_lint` accepts them despite the description saying never.
9. **Scope reach:**
   - `nested-cards` looks at ancestors outside the lint subtree.
   - `hero-eyebrow-chip` looks for the headline only inside the subtree.
10. **Stale docs** (Scrim divergences, report only):
    - ARCHITECTURE.md's "Lint profiles" says `expressive` relaxes only `oversized-h1` and `side-tab`.
    - Its Stage list says "22 of 41" rules are ported (now 30).
    - VENDORED.md's "Ported over measured rects" table still describes the superseded `clipped-overflow-container` (absolute/fixed, > 1px, outermost layer only).
    - The catalog name of `clipped-overflow-container` ("Positioned child clipped…") no longer matches its behaviour.
11. **API surface:** `LintOptions.only` and `category` exist but no tool exposes them.
12. **`severity: "advisory"`** in the catalog is dropped.
