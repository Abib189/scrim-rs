# Spec: `analyze_design`

**What it does:** reports what a document, or one node's subtree, actually uses, measured against the document's own tokens. It is read-only and deterministic: every list has a total order, and the same input gives byte-identical JSON.

**The four reports:**
- **colours:** by frequency, matched to colour tokens, with near-duplicate clusters and `var()` references;
- **type styles:** with inheritance, matched to typography tokens;
- **spacing values:** against the spacing tokens, or a 4 px grid when there are none;
- **repeated subtree shapes:** component candidates.

**Where it came from:**
- Scrim sources: `packages/engine/src/design/analyze.ts` and `colorDistance.ts`; the tool is in `packages/mcp/src/analyzeTools.ts`.
- It is Scrim's own code, re-derived from Scrim's OpenPencil study. No Impeccable code is in it, except `parseColor`, which it calls (`lint.md` §8 and §11).
- **Cases:** `../cases/analyze-design.json`, 8 cases on 5 documents, generated by running the real tool (§8).

## 1. The tool

- **Input:** `{ id?: string }`. With `id`, the scope is that node's subtree; without it, the whole document (every root in `rootIds` order).
- **Annotations:** `readOnlyHint: true`, `destructiveHint: false`, `idempotentHint: true`, `openWorldHint: false`.
- **Error:** `node not found: <id>` (`isError: true`).
- **Output:** one text block, `JSON.stringify(result, null, 2)`.

**Description, verbatim:**

```
Report what the document (or a node's subtree: pass id) actually uses, against its own tokens. Read-only. colors: every colour by frequency (hex, alpha kept), each matched to a colour token exactly or within ΔE 3, near-duplicate clusters with the value to keep, and var(--token) references. typography: text styles (family, size, weight, line height, letter spacing, inherited) by frequency, matched to typography tokens. spacing: gap / padding / margin values by frequency, off-scale ones flagged against the spacing tokens (a 4 px grid when there are none). repeated: subtrees of the same shape that appear more than once — component candidates (top 20). Use it to find drift before tidying a design; it never changes anything.
```

## 2. Output schema

```ts
interface DesignAnalysis {
  scope: string;                 // the id, or "(document)"
  nodes: number;                 // nodes visited (pre-order walk of the scope; §3)
  colors: {
    distinct: number;            // distinct colour values (before the 100 cap)
    values: Array<{ value: string; count: number; token: { name: string; deltaE: number } | null }>;  // ≤ 100
    nearDuplicates: Array<{ values: string[]; count: number; suggested: string; token: string | null; maxDeltaE: number }>;
    tokenRefs: Array<{ name: string; count: number }>;
    unparsed: number;
  };
  typography: {
    textNodes: number;
    distinct: number;            // before the 50 cap
    styles: Array<{ fontFamily: string | null; fontSize: string | null; fontWeight: string | null;
                    lineHeight: string | null; letterSpacing: string | null; count: number; token: string | null }>;  // ≤ 50
  };
  spacing: {
    scale: string;
    distinct: number;            // before the 100 cap
    values: Array<{ value: number; count: number; properties: { gap: number; padding: number; margin: number };
                    onScale: boolean; token: string | null }>;   // ≤ 100
    offScale: number[];
    unparsed: number;
  };
  repeated: Array<{ count: number; nodesEach: number; ids: string[]; names: string[]; shape: string }>;  // ≤ 20
}
```

**Limits** (`ANALYZE_LIMITS`): colours 100, typography 50, spacing 100, repeated 20, ids per repeat 10. Distinct names per repeat are capped at 3.

## 3. Shared rules

- **The walk.**
  - Pre-order, depth-first: a node, then its `childIds` in order.
  - It starts at each root in `rootIds` order, or at the scope node.
  - Every node reached counts in `nodes`, of any type, including component masters, instances and their children.
  - Nodes not reachable from the start are never seen.
- **A declaration** is `style[key] ?? layout[key]`, with an empty string treated as absent. The values are read **as declared**: no defaults and no units added.
  - The lint's `D` (layout, then style) differs only in that `''` in style would win there.
- **Sorting, `byCount(key)`:** count descending, then `key` ascending by JavaScript string comparison (UTF-16 code units).
- **`px(v)`** (analyze's own; it differs from the lint's):
  - the string must match `^(-?\d*\.?\d+)(px)?$`;
  - with the `px` suffix → the number;
  - without the suffix → the number **only if it is 0**, else `null`;
  - so a unitless string `"16"` is **not** a length here.
- **`round2(v)`** = `Math.round(v × 100) / 100`.
- **Token order.** Tokens are always considered in a fixed order: colours and typography by name (string order), spacing by value then name.

## 4. `colors`

**Colour-bearing properties, read in this order per node:** `color, background, backgroundColor, backgroundImage, border, borderColor, borderTop, borderRight, borderBottom, borderLeft, borderTopColor, borderRightColor, borderBottomColor, borderLeftColor, outline, outlineColor, textDecorationColor, boxShadow, textShadow, fill, stroke`.

**For each string value** (number values are skipped):
1. **`var()` references.**
   - Every match of `/var\(\s*--([\w-]+)[^()]*(?:\([^()]*\)[^()]*)*\)/g` counts **one reference to the token name** (the group).
   - The whole `var(…)`, **including its fallback**, is replaced by a space. So `var(--brand, #ff00aa)` counts `brand` once and never counts `#ff00aa`.
   - Only one level of nested parentheses is allowed inside a fallback. A nested `var()` inside a fallback is swallowed and not counted.
2. **Colour literals.**
   - Every match of `/#[0-9a-f]{3,8}\b|rgba?\([^)]*\)|\b(?:white|black|red|green|blue|gray|grey|transparent)\b/gi` in the rest is converted with `rgbaOf`.
   - A literal it cannot read (a 5- or 7-digit hex, `rgb(0 0 0)` space syntax) is dropped silently.
   - **`hsl()` and every other colour name are not literals.**
3. **`unparsed` += 1** when all of these hold:
   - no literal was found;
   - the rest is non-empty after trim;
   - the rest is not one of `none inherit initial unset currentcolor 0` (case-insensitive);
   - the **property name** matches `/color|^background$|^fill|^stroke/i`.
   - So `color: rebeccapurple` and `color: hsl(…)` count, but `backgroundImage: linear-gradient(hsl(…), …)` and `border: 1px solid hsl(…)` do **not** (case `promo/no-tokens`).

**Inline SVG paints** (`node.svg`) count like CSS colours, in drawing order:
- each shape's `fill` and `stroke`, unless absent, `none`, or starting `url(`;
- the children of `g`, recursively;
- then every `defs` entry's gradient `stops[].color`. `clipPath` and `mask` defs are skipped.
- Each paint goes straight to `rgbaOf`. An unreadable one (`currentColor`) is dropped, not counted as unparsed.

**`rgbaOf(s)`.** Trim and lower-case first, then:
- `transparent` → `(0,0,0,0)`;
- `#rgba` → each digit doubled, alpha = `aa/255`;
- `#rrggbbaa` → alpha = `aa/255`;
- otherwise the lint's `parseColor`:
  - `#rgb` and `#rrggbb`;
  - `rgb()` / `rgba()` with integer channels, comma syntax, alpha default 1;
  - the 7 names `white black red green blue gray grey` mapped to hex (`transparent` was handled above; `parseColor` itself returns `null` for it).

**`hexOf(c)`** = `#rrggbb` when `a ≥ 1`, else `#rrggbbaa`. Each channel is clamped to 0–255, rounded and written as 2 lower-case hex digits; alpha is written as `round(a × 255)`. The alpha is **kept**: a 50% black is `#00000080`, never merged into `#000000`. Colours are counted by this hex.

**`values`:** every distinct hex, sorted `byCount(hex)`, capped at 100, each with `token = tokenFor(colour)`.

**`tokenFor(c)`.**
- **The candidates:** `doc.tokens.colors` entries whose value `rgbaOf` reads, sorted by name.
- **Skip** a token whose `|alpha − c.alpha| > 0.02`.
- **Distance:** `d = 0` when the two hexes are equal, else **CIE76 ΔE**.
- **Keep** the candidate with `d ≤ 3` and `d` strictly below the best so far, so ties go to the first name.
- **Result:** `{ name, deltaE: round2(d) }`, or `null`.

**CIE76 ΔE, `deltaE76(p, q)`.** Alpha is ignored; the D65 white point is used:
- **Linearise:** each channel `v = c/255`, then `v ≤ 0.04045 ? v/12.92 : ((v+0.055)/1.055)^2.4`. Note the threshold differs from the lint's luminance, 0.03928. Keep both.
- **To XYZ:**
  - `x = (0.4124 R + 0.3576 G + 0.1805 B) / 0.95047`;
  - `y = 0.2126 R + 0.7152 G + 0.0722 B`;
  - `z = (0.0193 R + 0.1192 G + 0.9505 B) / 1.08883`.
- **To L\*a\*b\*:** `f(t) = t > 0.008856 ? cbrt(t) : 7.787 t + 16/116`, then:
  - `L = 116 f(y) − 16`;
  - `a = 500 (f(x) − f(y))`;
  - `b = 200 (f(y) − f(z))`.
- **ΔE** = the Euclidean distance between the two (L, a, b) points.

**`nearDuplicates`.** Clusters are built greedily over **all** distinct colours (not only the first 100), in `values` order:
1. **Seeds:** take each colour in turn as the seed. Skip it if it is already claimed, or if its alpha is 0.
2. **Members:** every unclaimed colour with alpha > 0, `|Δalpha| ≤ 0.02` against the seed, and `ΔE76(member, seed) ≤ 3`. The seed itself is included. Members stay in `values` order.
3. **Keep** the cluster only when it has `≥ 2` members, then claim them all.
4. **Each cluster:**
   - `values` = the member hexes;
   - `count` = the sum of their counts;
   - `suggested` = the seed's hex;
   - `token` = `tokenFor(seed)?.name ?? null`;
   - `maxDeltaE` = `round2(max ΔE76(member, seed))`.
5. **Sort** the clusters `byCount(suggested)`.

**`tokenRefs`:** `{ name, count }` per referenced name, sorted `byCount(name)`. Only colour-bearing properties are scanned, so a `var()` in spacing or typography is never a `tokenRef`.

## 5. `typography`

**The type values.** For each node, the five values `fontFamily, fontSize, fontWeight, lineHeight, letterSpacing`:
- take the parent's values, overlaid by the node's own declarations;
- convert each to a string with `String(v)`, so the number `16` becomes `"16"` and `1.5` becomes `"1.5"`;
- a value never declared up the chain is `null`.

**Where the values start.**
- **For the document:** all `null` at each root.
- **For a scope:** the values inherited from the scope node's ancestors (root first, each overlaid). The scope node's own declarations are then applied as usual.
- The values inherit through **every** node type.

**Counting.**
- Only nodes with `type === 'text'` count, **even with empty text**: `textNodes` = their number.
- Text nodes are grouped by the exact 5-tuple of strings; `distinct` = the number of groups.
- `styles` = the groups sorted `byCount(JSON.stringify(style))`, capped at 50.
  - The tie-break key serialises `{fontFamily, fontSize, fontWeight, lineHeight, letterSpacing, count, token}` in that key order, with `token` still `null` at sort time.

**Token match.** `token` = the name of the **first** `doc.tokens.typography` entry, by name order, that meets both conditions:
1. it has **at least one** key;
2. `sameValue(style[p], token[p])` holds for all five properties.

**`sameValue(styleValue, tokenValue)`:**
- the token does not set the property → true;
- the style value is `null` → false;
- otherwise, if both parse with analyze's `px` → numeric equality;
- else trimmed string equality.

**QUIRK (a likely bug):** analyze's `px` rejects unitless non-zero strings. So the number `72` (stringified `"72"`) does **not** match a token `"72px"`, and a style `"18px"` does **not** match a token `18`. Only the same spelling, or two px-suffixed strings, match. Case `article/typography`, styles `Canela/72` and `Tiempos/18px`.

## 6. `spacing`

**The properties, and their family:**
- `gap`, `rowGap`, `columnGap` → **gap**;
- `padding` and `paddingTop/Right/Bottom/Left` → **padding**;
- `margin` and `marginTop/Right/Bottom/Left` → **margin**.

**Reading a value** (per node, per property, in that order):
- **A number:** one value, used as is.
- **A string:** split on whitespace. For each part:
  - `px(part)` → the value;
  - `null` → `unparsed += 1`, unless the part is exactly `auto`.
  - So `5%`, `var(--space-md)`, `1rem` and a unitless `"16"` each count as unparsed. `calc(4px + 2px)` splits into 3 parts, all unparsed.
- **Counting:** a value of 0 is skipped. Others are counted **with their sign**, so −8 and 8 are distinct, and `properties[family]` is incremented.

**Spacing tokens.**
- Each `doc.tokens.spacing` entry is read as a number, or as a px string via analyze's `px`. Unreadable entries (`"24"` without px, `"1.5rem"`) are dropped.
- They are sorted by value, then by name.

**`values`:** sorted `byCount(String(value).padStart(12, '0'))`, capped at 100. That is JavaScript `padStart`: a negative value pads to `0000000000-8`, which sorts before positive values of equal count.

**Each value:**
- `token` = the name of the first token whose value equals `|value|`, or `null`;
- `onScale`:
  - with tokens → `token !== null`;
  - without tokens → `|value| % 4 === 0`, or `|value|` is 1 or 2 (`%` is the floating remainder).

**The rest:**
- `scale` = `spacing tokens (<token values joined ", ">)`, e.g. `spacing tokens (4, 8, 16, 24, 48)`, or exactly `4 px grid (no spacing tokens; 1 and 2 allowed)`. Values are printed as JavaScript numbers.
- `offScale` = the values (of all, not only the first 100) with `!onScale`, sorted ascending numerically.

## 7. `repeated` (component candidates)

**Excluded nodes:** every node in the subtree of a component master (`components[*].rootId`) or of an `instance` node, the root included.

**Shape of a node.** It is computed bottom-up:
- `head` = the type, then:
  - when `display` is declared, `:<display>`;
  - when that display is `flex` or `inline-flex`, also `-<flexDirection ?? 'row'>`.
  - Examples: `frame:flex-column`, `frame:grid`, `text`, `box`.
- `signature` = `head` plus the ordered list of the children's signatures.
- Names, text, sizes and colours are never part of it.
- `size` = the node count of the subtree.
- `label` = `head`, plus `(<child heads joined ", ">)` when the node has children. The label is one level deep; the signature is the whole tree.

**Grouping.**
1. Group the non-excluded nodes with `size ≥ 3` by signature, in walk order.
2. Keep the groups with `≥ 2` members.
3. **Drop implied groups:** drop a group when **every** member has a proper ancestor that is a member of a **different** kept group.
   - "Kept" means it passed step 2. A group can be dropped because of one that is itself dropped.
   - Case `dashboard/repeats`: the 12 cells inside the 12 rows are dropped.

**Each group's output:**
- `count` = the number of members;
- `nodesEach` = their size;
- `ids` = the first 10 member ids, in walk order;
- `names` = the first 3 distinct member names;
- `shape` = the first member's label, cut to 157 characters plus `…` (U+2026) when longer than 160.

**Sort:** count descending, then `nodesEach` descending, then the walk position of the first id. Cap at 20.

## 9. Points to settle in the port

1. The px/unitless mismatch in typography token matching (§5).
2. `hsl()`, `hwb()`, `lab()`, `oklch()` and the CSS named colours beyond these 7 are invisible to `colors`. Some of them count as `unparsed`, but only on colour-named properties (§4).
3. A `var()` in spacing counts as `unparsed`, not as a token reference.
4. Text nodes inside component masters and instances count in `typography`, but those subtrees are excluded from `repeated`. That is deliberate in `repeated`; undocumented for typography.
5. `transparent` is counted as the colour `#00000000`, but it never joins a cluster.
